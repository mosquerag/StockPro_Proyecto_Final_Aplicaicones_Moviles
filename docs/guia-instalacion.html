Guía de instalación y despliegue

StockPro funcionando en tu equipo, paso a paso.

Requisitos, base de datos, backend Spring Boot y app Android. Todos los comandos tienen botón Copiar, y las dos rutas —Docker o PostgreSQL nativo— están explicadas con el SQL exacto.

25–40 minutos Windows · PowerShell Emulador o USB Flyway V1–V3

3 Preparar PostgreSQL

Elige una de las dos opciones. No ejecutes ambas sobre el mismo puerto 5432.

Desde la raíz del repositorio:

PowerShell · Docker Compose 
docker compose up -d
docker compose ps
El contenedor se llama stockpro-postgres, expone el puerto 5432 y crea la base stockpro_db, el usuario stockpro_user y la contraseña stockpro_password. Las tablas las crea Flyway al arrancar Spring Boot.

Comandos útiles

PowerShell · Docker Compose 
# Ver logs
docker compose logs -f postgres

# Detener sin borrar datos
docker compose stop

# Reiniciar desde cero (borra el volumen)
docker compose down -v
docker compose up -d

Instala PostgreSQL 16 y abre pgAdmin 4 o la consola psql como superusuario postgres. Ejecuta este SQL exacto:

pgAdmin 4 · Query Tool 
-- 1. Usuario y base de datos
CREATE USER stockpro_user WITH PASSWORD 'stockpro_password';
CREATE DATABASE stockpro_db OWNER stockpro_user;
GRANT ALL PRIVILEGES ON DATABASE stockpro_db TO stockpro_user;

-- 2. Conéctate a stockpro_db y habilita la extensión
CREATE EXTENSION IF NOT EXISTS "pgcrypto";
No crees tablas a mano. Flyway aplica V1, V2 y V3 automáticamente cuando arranca el backend. Si pgcrypto falla por permisos, ejecuta CREATE EXTENSION una vez como superusuario.

Comprobar la conexión

PowerShell · psql 
psql -h localhost -U stockpro_user -d stockpro_db -c "SELECT version();"

Si tu PostgreSQL usa otras credenciales, defínelas con las variables DB_* antes de arrancar el backend.

4 Ejecutar el backend

Si usaste los valores por defecto de Docker o del SQL anterior, no necesitas configurar variables de entorno.

Arrancar Spring Boot

PowerShell · Java 17 + Maven 
cd backend
mvn spring-boot:run
Si no tienes Maven instalado, abre backend/pom.xml en IntelliJ IDEA o Android Studio con el plugin de Java y ejecuta la clase StockProApplication.

Variables de entorno (opcional)

Los valores por defecto están en application.yml. Si tu PostgreSQL usa otras credenciales:

PowerShell · variables de entorno 
$env:DB_HOST="localhost"
$env:DB_PORT="5432"
$env:DB_NAME="stockpro_db"
$env:DB_USER="stockpro_user"
$env:DB_PASSWORD="tu_password"

5 Abrir y ejecutar la app Android

La app usa http://localhost:8080/. Para que ese localhost apunte a tu computador desde el emulador o el teléfono, ejecuta el reverse antes de abrir la app.

Abrir el proyecto

  1. Abre Android Studio.
  2. Selecciona Open y elige la raíz del repositorio (donde está settings.gradle.kts), no la carpeta app.
  3. Espera la sincronización de Gradle. El proyecto usa AGP 9.1.1, Kotlin 2.2.10 y Gradle 9.3.1.
  4. Acepta la instalación de los SDK que falten (API 36 para compilar).
  5. Verifica que el módulo app aparezca en la barra de proyectos.

Conectar el dispositivo

Inicia un emulador API 30 o superior (API 24 es el mínimo). Luego ejecuta:

PowerShell · Windows · ruta completa de adb.exe 
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse --list

Debe aparecer tcp:8080 tcp:8080. Si adb está en el PATH, puedes usar adb reverse tcp:8080 tcp:8080.

  1. Activa las Opciones de desarrollador y la Depuración USB en el teléfono.
  2. Conecta el cable USB y autoriza el equipo cuando aparezca el aviso en el teléfono.
  3. Ejecuta los comandos y confirma que el dispositivo aparece como device.
PowerShell · Windows · ruta completa de adb.exe 
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse --list
Si el teléfono no aparece, revisa el cable, acepta la autorización de depuración y prueba con adb kill-server seguido de adb devices. También puede ser el firewall de Windows.

Ejecutar la app

  1. Selecciona el módulo app y el dispositivo en la barra superior.
  2. Pulsa Run ▶.
  3. Espera la instalación y abre StockPro.
  4. Inicia sesión con una de las cuentas demo.

Compilar el APK por consola (opcional)

PowerShell · Gradle 
gradle :app:assembleDebug
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app/build/outputs/apk/debug/app-debug.apk

Con Gradle instalado y JAVA_HOME en Java 17. El APK queda en app/build/outputs/apk/debug/app-debug.apk.

Alternativas si adb reverse no está disponible: en el emulador la IP del host es 10.0.2.2; en un teléfono de la misma red puedes usar la IP local del PC. Ambas variantes requieren ajustar DEFAULT_BASE_URL en el código, por eso el flujo recomendado es adb reverse.

7 Solución de problemas frecuentes

Los síntomas más comunes al montar el entorno local y cómo resolverlos.

  • Connection refusedEl backend está apagado o falta el reverse. Arranca Spring Boot y ejecuta adb reverse tcp:8080 tcp:8080.
  • El reverse no apareceEjecuta adb reverse --list. En Windows usa la ruta completa de adb.exe si no está en el PATH.
  • Firewall o IP incorrectaPermite el puerto 8080, revisa que el backend escuche en localhost:8080 y que el dispositivo esté autorizado.
  • Cleartext HTTP not permittedVerifica network_security_config.xml. En producción usa HTTPS.

  • Port 8080 was already in useEjecuta netstat -ano | findstr :8080, termina el proceso o cambia server.port en application.yml.
  • password authentication failedLas credenciales no coinciden. Define DB_USER y DB_PASSWORD o recrea el usuario.
  • database "stockpro_db" does not existCréala en pgAdmin o con CREATE DATABASE y vuelve a arrancar el backend.
  • relation "productos" does not existLa app arrancó antes de que Flyway terminara. Espera el mensaje “Successfully applied” y reinicia.

  • Validate failed: checksum mismatchSe editó una migración ya aplicada. No edites V1–V3: restaura la base o ejecuta flyway repair si sabes lo que haces.
  • Flyway no crea tablasVerifica que spring.flyway.enabled=true y que existan los archivos en db/migration.
  • Base de una versión anteriorSi no necesitas los datos, reinicia con docker compose down -v y docker compose up -d.

  • Gradle no sincronizaConfigura JDK 17 en Android Studio e instala el SDK 36. Abre la raíz del repositorio, no la carpeta app.
  • OutOfMemoryError en GradleAjusta org.gradle.jvmargs y cierra procesos. Revisa la sección de RAM.
  • Emulador muy lentoActiva VT-x/AMD-V e instala el acelerador del emulador. Usa una imagen API 30 con 2 GB.
  • El idioma no cambiaVerifica values-en/strings.xml y reinicia la actividad.

8 Optimización de RAM y recursos

El proyecto ya trae ajustes en gradle.properties. Ajusta según la memoria de tu equipo:

8 GBorg.gradle.jvmargs=-Xmx2g. Cierra Docker si usas PostgreSQL nativo y usa un emulador API 30 con 2 GB.
16 GBMantén -Xmx4g. Docker con 2 GB y emulador con 2–3 GB.
32 GB o más-Xmx6g. Puedes dejar Docker y el emulador abiertos.

Otras acciones

  • Detén el daemon al terminar: gradle --stop.
  • Compila solo lo necesario: gradle :app:assembleDebug.
  • Usa modo offline si ya tienes dependencias: gradle :app:assembleDebug --offline.
  • Cierra el emulador cuando no lo uses: consume más RAM que el backend.
  • Docker Desktop → Settings → Resources: 2 GB son suficientes para PostgreSQL.
  • El backend con mvn spring-boot:run usa ~300–500 MB; no necesitas asignar más.

9 Checklist final

Antes de entregar o sustentar, confirma estos puntos:

  • PostgreSQL arriba y base stockpro_db creada.
  • Flyway aplicó V1, V2 y V3 sin errores.
  • Backend responde en http://localhost:8080.
  • Swagger muestra los 37 endpoints.
  • Login demo funciona y devuelve tokens.
  • App compila e instala en emulador o teléfono.
  • Smoke test completo (sección 6).
  • Landing y guía abren sin errores.
  • PDF generado en docs/StockPro_Entrega_ABP_Actualizado.pdf.
  • git status sin cambios en código funcional.
